## 🎯 CÁC NGUYÊN TẮC CỐT LÕI (UI/UX, SECURITY & RUNTIME)

1. 🔴 **Quy chuẩn Màu Thông Báo (Toast Notification UX):**
   * **Thông báo Lỗi (Error):** Luôn cố định màu **Đỏ cảnh báo chuẩn** (`#DC2626` / `#EF4444`), không đổi màu.
   * **Thông báo Thành công (Success):** Tự động đổi màu nền/viền/icon theo **Bảng màu chủ đề (Theme Palette)** đang chọn.
   * **Cấu trúc Toast chuyên nghiệp:** Hỗ trợ 2 dòng (Tiêu đề in đậm + Nội dung chi tiết + Nút đóng nhanh).
2. 🧠 **Bộ Dịch Lỗi Thông Minh (Error Translator Engine):**
   * Tuyệt đối không để lọt các mã lỗi kỹ thuật như `Lỗi HTTP 500`, `HTTP_404`, `ECONNREFUSED`, `[object Object]` hay mảng validation thô lên giao diện người dùng.
   * Toàn bộ mã lỗi phải được dịch sang câu tiếng Việt nhân văn và hướng dẫn hành động cụ thể.
3. 🚫 **Tuyệt đối KHÔNG dùng Popup/Modal (No Popup Policy):**
   * Sử dụng **Inline Expandable Form / Slide-down Drawer** mượt mà tại chỗ cho mọi thao tác.
4. 📐 **Chuẩn hóa Container `max-w-7xl`:**
   * Đồng nhất độ rộng toàn bộ các trang Seller Portal & Admin Portal về chuẩn `max-w-7xl mx-auto px-4 sm:px-6 lg:px-8`.
5. 🛡️ **Enforcement Phân Quyền Đa Tầng (Frontend & Backend):**
   * Frontend: Ẩn/hiện menu sidebar và vô hiệu hóa nút bấm theo danh sách quyền `can(permission)`.
   * Backend: Trả về `403 Forbidden` rõ ràng khi nhân viên hoặc user cố tình gọi API ngoài phạm vi cấp quyền.
6. ⚡ **Môi trường & Runtime:**
   * Backend Gateway (Port `3000`), Database Docker và Frontend Web (Port `3100`) **đang chạy sẵn sàng**.
   * **KHÔNG** chạy lệnh khởi động lại hoặc tắt các tiến trình/port đang chạy.
   * Kiểm thử UI/UX trực tiếp tại `http://localhost:3100`.

### 📦 PHẦN 3: Kịch Bản E2E Order Fulfillment & Granular RBAC Negative Enforcement (Sprint 34C)
* **Mục tiêu:** Kiểm thử luồng xử lý đơn hàng của Admin con và kiểm tra bảo vệ phân quyền đa tầng (Positive & Negative RBAC).
* **Chi tiết công việc:**
  1. Luồng 1 (Positive RBAC): Admin con (Staff có quyền `ORDER_VIEW`, `ORDER_PROCESS`) mở Side Drawer chi tiết đơn hàng $\rightarrow$ Thực hiện Xác nhận (`CONFIRMED`) $\rightarrow$ Đóng gói (`PROCESSING`) $\rightarrow$ Bàn giao giao hàng (`SHIPPED`) $\rightarrow$ Hoàn tất đơn (`DELIVERED`).
  2. Luồng 2 (Negative RBAC): Admin con cố tình truy cập vào trang Tạo sách hoặc gọi API `POST /books` (không có quyền `PRODUCT_CREATE`) $\rightarrow$ Frontend ẩn nút/menu và hiển thị cảnh báo 403; Backend Gateway chốt chặn trả về HTTP `403 Forbidden`.
  3. Xây dựng script verify Part 3: `scripts/verify-phase9-part3.mjs`.
* **Tiêu chí nghiệm thu:** Đơn hàng chuyển trạng thái hoàn tất thành công; Admin con bị từ chối `403` an toàn khi vi phạm phân quyền.
* 🛑 **ĐIỂM DỪNG 3:** Dừng lại, báo cáo kết quả để bạn nghiệm thu.
